# UI/UX audit and V2 implementation — 9 October 2026

The existing public site was inspected with screenshots and browser interaction tests at **320, 375, 390, 768, 1024 and 1440 pixels**. Source research and family-specific preferences remain in the separate PRIVATE repo.

## Findings, decisions and deployed changes

| Issue | Review finding | Change made |
|---|---|---|
| Content buried below introduction | Phone and desktop users had to scroll a long way to see outings | Date-selected searches hide the decorative hero; the hero remains for all-dates browsing |
| One giant result list | Roughly 69 matches displayed at once | Split date-listed/weekly items from unverified-open venues, initially show 18 cards, then load more |
| Inaccurate distance semantics | The 45-minute band excluded local options | Travel bands now cumulative (local included in 45-minute range) |
| Weak mobile filtering | A long expanding sidebar displaced the content | Modal-style bottom drawer, keyboard trap, Escape/backdrop close, results count, one-tap chips |
| Poor event certainty | Calendar and cards could make usual sessions seem guaranteed | Clearly distinguish a listed date, usual weekly session, and attraction opening not confirmed |
| Mapping failure and crowding | Original Leaflet CSS URL had a mismatched SHA integrity value; map tiles laid out wrongly and pins overlapped | Bundle vetted Leaflet CSS/JS locally, cluster approximate area markers, link map selections to area list |
| Tiny/awkward controls | Some card details were hard to reach near the fixed mobile navigation | Larger tappable controls, clickable activity titles, additional scroll clearance and focus styles |
| Low contrast | axe-core initially flagged many muted text labels | Darker text accent palette, keeping pastel backgrounds; post-change automated WCAG A/AA scan passes |
| Bad classifications | 11 entries had misleading categories or locations, including the National Space Centre mapped to Nottingham | Corrected categories and approximate area points, archived unverified leads |
| Difficult content updates | 33 hand-written summaries were hard-coded in JavaScript | Moved summaries into editable activity JSON |
| Disconnected date selection | Clicking a calendar day did not update the main date field/URL | Calendar selection now synchronises date throughout the app |
| Static-only checks | No repeatable browser/accessible UI tests | Add responsive smoke tests and automated accessibility checks to GitHub Actions |

## Verification

- JSON schema, references, date validity and privacy checks: `python3 scripts/validate_catalogue.py`
- JavaScript syntax: `node --check app.js`
- End-to-end browser UI: `npm run test:ui`, covering 320px, 390px, 768px and 1440px, search/filtering, page loading, map clustering, activity opening, saved favourites, calendar date sync, runtime errors and axe-core WCAG 2.0/2.1 A/AA.
- Initial manual screenshot review also included 375px and 1024px widths.
- All builds are static GitHub Pages; private information is never bundled with the published site.

## Honest remaining limitations and follow-ups

1. This is still a **discovery catalogue**, not live opening-hours verification or a reservation provider. October 2026 source checks become stale; the website indicates old research, and future dates need primary-source checks.
2. Calendar weekly sessions can be cancelled, especially outside term dates. Displaying a session is not proof that spaces are available.
3. Map points are **approximate area centroids**, not verified venue entrances, and distance filters represent broad categories rather than live road journey times.
4. Favourites remain browser-local. Cross-device sync would require deliberate privacy-conscious authentication.
5. New suggestions and visit feedback currently use private GitHub issue templates. More streamlined private feedback could be a later enhancement.
6. Automated axe testing complements but does not replace manual VoiceOver/TalkBack testing or a full inclusive-design review.
7. A background source-monitoring/data-enrichment workflow is separate and **not yet configured**. GitHub Pages auto-publishing and CI testing do work.

## Editorial rules

Dates, prices, age restrictions, venues and source provenance must be checked before presenting them as fact. Do not publish exact family location or personal routines. Avoid presenting an unverified lead as a date-confirmed event. Don't generate day-long itineraries unless the selected activity inherently requires one.
